## 页2：讲述你要做什么

**研究目标：** 设计并实现一套基于深度学习的车险理赔预测系统。

**具体要做的事情：**

1. **构建一个完整的三层架构业务系统：**
   - 前端：Vue3 + ElementPlus + ECharts，提供交互式管理界面和数据可视化
   - 后端：Spring Boot + MyBatis + MySQL，实现保单、理赔、车辆信息等业务数据的CRUD管理与统计分析
   - ML服务：FastAPI + PyTorch，将训练好的深度学习模型部署为独立推理服务

2. **构建车险理赔预测深度学习模型：**
   - 基于多层感知机（MLP）构建二分类模型，预测保单在当前年度是否发生理赔
   - 对公开车险数据集（105,555条记录，30个变量）进行数据清洗、缺失值填充、特征工程和标准化预处理
   - 解决数据类别不平衡问题（正负样本比约1:4.37）
   - 引入残差连接、层归一化、不确定性加权损失函数等优化手段提升模型性能

3. **实现"数据管理—模型预测—结果分析"的完整业务闭环**，为车险行业理赔风控的数字化转型提供可落地的原型方案。

## 页3-4：讲述你具体是怎么做的（重点体现自己的工作量）

### 一、数据处理与特征工程（第4章）

- **缺失值处理**：对3个缺失字段设计了差异化策略——Data_Lapse字段（66.7%缺失）直接丢弃；Length字段按车辆类型分组用中位数填充；Type_fuel字段按车辆类型分组用众数填充
- **异常值处理**：对右偏严重的数值字段执行99.9分位截断，保留合理高值样本的同时消除极端异常值干扰
- **日期特征工程**：设计统一的参考日期锚点（保单合同开始日期），将5个原始日期字段解析为有业务语义的派生特征——驾龄、投保人年龄、保单年限、车龄、相对天数差
- **特征标准化**：使用StandardScaler，严格遵循数据隔离原则（仅在训练集上fit，再transform验证集和测试集），scaler对象序列化保存以支持离线推理
- **类别不平衡应对**：分层抽样（两次split均使用stratify参数）、损失重加权（pos_weight=3.10）、标签平滑、自动阈值搜索的组合策略

### 二、模型结构设计与优化（第4章）

- **主干网络**：设计了"输入投影层 + 4个残差块"的沙漏型结构（128→256→256→128→128），包含残差连接、LayerNorm、GELU激活函数、Dropout正则化
- **残差块封装**：将残差连接、双线性层、LayerNorm、GELU、Dropout封装为可复用的ResidualBlock类，维度不一致时通过无偏置线性投影对齐
- **分类头设计**：128→32→1的压缩结构，训练时head_samples=10（多次前向取平均），结合Dropout形成近似头部采样集成
- **损失函数**：带正类权重的BCEWithLogitsLoss + 标签平滑，同时解决样本不平衡和过拟合

### 三、训练策略设计（第4章）

- **自动阈值搜索**：每个epoch后在验证集上搜索200个候选阈值（0.05~0.95），以Fβ（β=1.3偏重召回率）为目标，同时约束Recall≥0.830
- **Cosine Warmup学习率调度**：前期LinearLR线性预热 + 中后期CosineAnnealingLR余弦退火
- **Early Stopping**：以AUC为监控指标（不依赖固定阈值，对类别不平衡更稳健）
- **AMP混合精度训练 + 梯度裁剪**提升训练效率和数值稳定性
- **消融实验**：完成了类别不平衡处理消融实验和网络结构消融实验，定量分析了各组件贡献

### 四、系统实现（第5章）

- **十大功能模块**：用户认证、系统概览、保单信息管理、保单统计分析、理赔记录管理、理赔统计、车辆信息管理、理赔率预测管理、理赔率预测统计、模型训练
- **权限体系**：ADMIN和STUDENT（普通用户）双角色，普通用户数据隔离（只能访问自己创建的数据）
- **业务关联约束**：保单→车辆信息/理赔记录通过保单编号ID级联，保证数据完整性
- **待办事项**：系统首页自动统计缺失理赔记录/车辆信息的保单
- **保单分析/理赔分析**：多维度可视化分析，支持自定义分析目标、统计指标、图表类型、排序指标、筛选条件
- **模型训练管理**：管理员可配置超参数（优化器、学习率、阈值搜索目标等）、管理训练样本库（批量按年份导入、重复数据覆盖、残缺数据过滤）
- **预测结果解释**：单特征局部消融解释，提取Top3风险提升因素和Top2风险缓释因素

## 页5：创新点、解决的问题与实现难点

### 一、相比同类毕业设计题目的创新点

1. **不是单纯的模型对比研究，而是完整的系统工程**：将数据处理、模型训练、在线推理、业务管理、可视化分析整合到统一平台中，实现了从算法到系统的完整闭环

2. **残差MLP网络结构的沙漏型设计**：不同于普通MLP直接堆叠全连接层，本文设计了128→256→256→128→128的沙漏型宽度变化，先扩宽再精炼，并引入ResidualBlock作为基本构建单元

3. **自动阈值搜索机制**：摒弃固定的0.5分类阈值，基于验证集在200个候选阈值中搜索，以Fβ+召回率下限约束为优化目标，使决策边界更贴合"宁可多报、尽量不漏"的车险业务需求

4. **类别不平衡的组合解决方案**：将分层抽样、加权损失函数、标签平滑、自动阈值搜索四种策略有机组合，并通过消融实验验证了各策略的独立贡献

5. **预测结果的可解释性**：设计了单特征局部消融解释方法，识别出影响预测结果的主要风险提升因素和风险缓释因素，增强了模型输出对业务人员的可理解性

6. **训练样本库管理机制**：支持按年份批量导入、重复数据可选择覆盖更新、残缺数据自动过滤，实现了从业务数据到训练数据的规范化流转

### 二、解决的以往同类题目未解决的问题

1. **业务数据与ML模型的深度集成**：以往同类毕设往往是模型和数据管理分离，本文解决了从MySQL业务表→CSV导出→模型训练→FastAPI部署→SpringBoot代理→前端展示的完整链路

2. **用户数据隔离与权限控制**：实现了ADMIN/STUDENT双角色权限体系，普通用户仅可访问自身数据、使用管理员训练好的模型，解决了多用户场景下的数据安全问题

3. **模型的持续迭代与版本管理**：管理员可以选择保存或丢弃训练结果，模型更新只需替换权重文件，无需改动业务系统代码

### 三、实现难点及解决方法

| 难点 | 解决方法 |
|------|----------|
| **正负样本严重不均衡（1:4.37）** | 分层抽样保证各子集比例一致 + pos_weight=3.10的加权BCE损失 + 标签平滑防过拟合 + 自动阈值搜索校正决策边界偏移 |
| **日期字段是字符串，神经网络无法直接处理** | 设计参考日期锚点体系，提取驾龄、投保人年龄、保单年限、车龄等有明确业务语义的派生数值特征，并标准化处理 |
| **缺失值处理策略的选择** | 对不同字段采用差异化策略——业务上不适用的直接丢弃（Data_Lapse）、连续值分组中位数填充（Length）、离散值分组众数填充（Type_fuel） |
| **深层网络训练不稳定、梯度传播困难** | 引入残差连接 + LayerNorm归一化 + GELU激活 + Cosine Warmup学习率预热 + 梯度裁剪，训练损失和验证损失均平滑收敛 |
| **前后端 + Python ML三端技术栈集成** | FastAPI将PyTorch模型封装为独立HTTP服务，SpringBoot通过hutool HTTP客户端代理转发请求，实现解耦部署 |
| **保单-车辆-理赔三大业务模块的数据一致性** | 以保单编号ID为外键建立级联约束，必须先创建保单才能补充车辆信息和理赔记录，系统首页待办事项自动检测数据缺失 |
| **如何判断模型何时停止训练** | 以AUC（而非准确率或固定阈值的F1）作为Early Stopping监控指标，因为AUC不依赖具体阈值，对类别不均衡更稳健 |
